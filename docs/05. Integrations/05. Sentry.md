# Sentry

Sashakt uses [Sentry](https://sentry.io) for error tracking. When something breaks — in the API, the Portal, or the candidate Webapp — Sentry captures the error with enough context to debug it.

## Why Sentry matters

In a production deployment serving real candidates, you don't want to find out about issues from a candidate's WhatsApp message. Sentry tells your team within seconds.

## Connecting Sentry

Each of the three Sashakt apps has its own Sentry DSN configured at deploy time:

- **sashakt-core** — Backend API errors, sync failures, certificate generation errors
- **sashakt-portal** — Admin-side UI errors
- **sashakt-webapp** — Candidate-side UI errors

If you're hosting Sashakt yourself, your DevOps team enters DSNs into each app's environment configuration before deploying.

## What Sentry captures

- Stack traces for backend exceptions
- JavaScript errors in the browser
- Performance traces for slow API calls (optional)
- Breadcrumb-style trails of what the user did just before the error

Sashakt **does not** send personally identifiable candidate data (names, phone numbers, answers) to Sentry — only technical context.

## Common alert configuration

In your Sentry project, set alerts for:

- Any new issue introduced after deploy
- Spike in errors over baseline
- Errors affecting more than X candidates in Y minutes

Send alerts to a Slack or email channel your on-call rotation watches.
