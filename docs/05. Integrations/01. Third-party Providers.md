# Integrations

Sashakt integrates with three **Google Cloud services** to handle analytics, file storage, and certificate generation. Each is modeled as a "provider" — a named service connection that gets configured per organization using a Google service account.

## The three providers

| Provider | Purpose |
|----------|---------|
| **BigQuery** | Syncs assessment data (submissions, responses, tests, questions) to your data warehouse for analytics and reporting |
| **Google Cloud Storage (GCS)** | Stores media files — images, audio, and video — attached to questions and assessments |
| **Google Slides** | Renders certificates from a Google Slides template and exports them as PDFs for candidates |

These three providers cover everything Sashakt needs from external services. There is no generic "external API" connector — the integrations are specific to these Google Cloud products.

## How providers are configured

Each organization has its own provider configuration. The configuration for each provider is a **Google service account JSON key** — the same credential format used across Google Cloud services.

For BigQuery, you also specify:
- A **dataset ID** — Sashakt automatically appends an organization-specific suffix (`_<org_id>`) to keep each organization's data isolated within the same Google Cloud project.
- Sync settings (batch size, incremental mode).

For GCS, you also specify:
- A **bucket name** — where media files will be stored.
- Signed URL expiration time (default: 4 hours).

## Security

- All provider credentials (service account JSON keys) are **encrypted at rest** using a Fernet symmetric key before being stored in the database.
- Credentials are **never returned to the browser** — only sync status and timestamps are exposed through the API.
- Provider configuration can only be created or changed by users with the `create_provider` / `update_provider` permissions (System Admins).

:::caution Rotate service account keys
Treat service account JSON keys like passwords. Rotate them on a schedule, and immediately if anyone with platform access leaves your organization. Update the provider configuration with the new key after rotation.
:::

## Testing a provider connection

After configuring a provider, a test-connection endpoint is available to verify that Sashakt can reach the service with the stored credentials. A successful test confirms the service account has the right permissions.
