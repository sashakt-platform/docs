# Users & Permissions

The **Users** section is where you add the people who run tests for your organisation. Sashakt's permission model is role-driven — assigning the right role is the main lever you have.

![Users list](/img/screenshots/users.png)

## Adding a user

1. Open **Users** from the left navigation.
2. Click **Create User**.
3. Fill in **Name**, **Email**, and **Phone Number**.
4. Choose a **Role** — System Admin, State Admin, or Test Admin (see [User Roles](../getting-started/user-roles) for what each can do).
5. Set a **Password** and confirm it. Share it with the user via a secure channel — they can change it later in their profile.
6. Click **Save**.

![Create user with role dropdown](/img/screenshots/user-create-roles.png)

## Editing or deactivating a user

Click any user row to open their profile. From there you can:

- Update their name, email, phone, or role
- Reset their password
- **Deactivate** the account — keeps history intact but blocks login

:::tip Deactivate, don't delete
Deactivating preserves the user's name on the tests and questions they touched. Deletion is best reserved for compliance-driven removal.
:::

## Filtering and searching

The Users list supports filtering by status. Use these when your org grows large enough that scrolling becomes painful.

## How permissions actually work

Sashakt enforces permissions on the **server side**, not just in the UI. A user can never see or change data outside their role's scope, even if they try to manipulate URLs. You don't need to worry about hidden permissions leaking — what you see in [User Roles](../getting-started/user-roles) is exactly what each role can touch.
