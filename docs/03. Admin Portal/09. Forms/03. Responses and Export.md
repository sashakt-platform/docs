# Responses & Export

Every candidate who fills in a form leaves a response behind. This page covers reviewing those responses and exporting them.

> _📷 Screenshot placeholder: Responses table_

## Where responses live

Form responses are stored alongside the candidate's test submission. You can view them in two places:

- **Forms → Responses** — A flat list of responses grouped by form.
- **Submissions → Open a candidate** — The same response shown next to that candidate's test attempt.

The two views show the same data — pick whichever fits your task.

## Filtering responses

Filter by:

- **Date range**
- **Test** (if a form is attached to multiple tests)
- **Specific field values** — e.g. all candidates from _Pune District_, or all candidates whose age is between 14 and 16

## Exporting

Click **Export** to download a CSV. Each row is one candidate's response; each form field is a column.

If a form has changed over time (you added a field last week), older responses leave that column blank — the export preserves the structure exactly as it was when responses came in.

:::tip Long-term storage
Exports are point-in-time snapshots. For automated, ongoing analytics, set up [BigQuery Sync](../../integrations/bigquery-sync) — responses stream to BigQuery as they arrive.
:::

## Deleting responses

You can delete a single response if needed (e.g. a test attempt by a duplicate registration). Deletion is permanent. For compliance-driven data deletion, follow your organization's data retention policy.
