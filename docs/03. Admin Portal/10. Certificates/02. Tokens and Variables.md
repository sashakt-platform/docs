# Tokens & Variables

Tokens are placeholders you drop into a certificate that get replaced with real values at issuance time. They're what make one template work for thousands of candidates.

> _📷 Screenshot placeholder: Inserting a token in the certificate designer_

## Available tokens

| Token | Replaced with |
|-------|---------------|
| `{{candidate_name}}` | Candidate's full name |
| `{{test_name}}` | The test's name |
| `{{score}}` | Numeric score (e.g. `45`) |
| `{{score_percentage}}` | Score as a percentage (e.g. `90%`) |
| `{{date}}` | Date the test was completed |
| `{{certificate_id}}` | Unique certificate ID |
| `{{verification_url}}` | Public URL to verify this certificate |
| `{{organization_name}}` | Your organization's name |
| `{{state}}` | Candidate's registered state |
| `{{district}}` | Candidate's registered district |

You can add **custom tokens** that map to any form field — e.g. `{{batch_code}}` or `{{employee_id}}`.

## Inserting a token

In the certificate designer:

1. Add a **text block**.
2. Type or paste a token like `{{candidate_name}}` into the block.
3. Style it (font, size, alignment) just like normal text.

You can mix tokens with static text:

```
Awarded to {{candidate_name}}
for scoring {{score_percentage}} on {{test_name}}.
```

## Verification URL

Every certificate carries a `{{verification_url}}` — a public link a third party (employer, school, partner) can open to confirm the certificate is real. Sashakt shows them the candidate's name, the test, the date, and the score.

Include the verification URL on every certificate, usually at the bottom in small text. It is the difference between a certificate that's trusted and one that isn't.
