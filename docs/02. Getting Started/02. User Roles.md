# User Roles

Sashakt uses **roles** to decide who can do what. Each role has a clear scope — some manage the whole platform, others manage a single organization, and some only see data from their own state or district.

If a button or menu is missing from your view, it's usually because your role doesn't include that permission. That's by design.

## The roles at a glance

| Role | Scope | What they do |
|------|-------|--------------|
| **Super Admin** | Whole platform | Run the platform; create organizations; manage other admins |
| **System Admin** | One organization | Run a single org; manage its users, tests, questions, settings |
| **State Admin** | One state | Manage tests, candidates, and reports for a specific state |
| **District Admin** | One district | Same as State Admin, scoped further to a single district |
| **Test Admin** | Assigned tests | Create and manage tests; add questions; review submissions |
| **Candidate** | Themselves | Register for tests, take them, and download certificates |

## Super Admin

The Super Admin sits at the top of the hierarchy. They can:

- Create and configure **organizations**
- Promote users to **System Admin** of any organization
- See platform-wide analytics
- Toggle platform-level features

There are usually only one or two Super Admins. If you're not sure who yours is, ask your System Admin.

## System Admin

The System Admin runs a single organization end-to-end. They can:

- Manage all **users** in their org (create, edit, deactivate)
- Set **organization settings** — feature toggles, platform nomenclature, guides, analytics
- Create and edit any **test**, **question**, **tag**, **form**, **certificate**, or **entity**
- View all **submissions** and reports for their org

If you're the person setting up Sashakt for your organization, you're probably a System Admin.

## State Admin and District Admin

These are **scoped** roles — they look a lot like a System Admin, but only for data belonging to their state (or district).

A State Admin in Maharashtra can:

- See tests and candidates assigned to Maharashtra
- Add and manage users within Maharashtra
- Review submissions from candidates registered in Maharashtra

…but cannot see anything from Karnataka.

District Admins work the same way, just one level deeper.

:::info Why scoped roles?
Many Sashakt deployments cover large geographies. Scoped roles let regional teams manage their work without seeing — or accidentally editing — other regions' data.
:::

## Test Admin

A Test Admin focuses on **building and running tests**. They can:

- Create and edit tests
- Add and edit questions in the question bank
- View submissions for tests they manage

They typically don't manage users, organization settings, or platform-wide configuration.

This role is a good fit for subject-matter experts, training coordinators, or content authors who shouldn't have full admin access.

## Candidate

The Candidate is the person taking the test. They don't log in to the Portal — they use the **Sashakt Webapp** instead, where they:

- Register for a test using a public link
- Fill in any required information
- Take the test in single-choice, multi-choice, subjective, numerical, or matrix formats
- See their score (if the test allows it)
- Download a certificate (if the test issues one)

Candidates never see the Portal, and admins manage candidates from the Portal side.

## How to tell which role you have

Open your **Profile** page in the Portal. Your role is shown at the top.

If your role doesn't match what you expected, ask your System Admin (or Super Admin) to update it. Roles can be changed at any time.
