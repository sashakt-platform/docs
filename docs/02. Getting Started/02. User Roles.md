# User Roles

Sashakt uses **roles** to decide who can do what. Each role has a clear scope — some manage an entire organization, others only see data from their own state or district.

If a button or menu is missing from your view, it's usually because your role doesn't include that permission. That's by design.

## The roles at a glance

| Role | Scope | What they do |
|------|-------|--------------|
| **System Admin** | One organization | Run a single org; manage its users, tests, questions, settings |
| **State Admin** | One state | Manage tests, candidates, and reports for a specific state |
| **Test Admin** | Assigned tests (optionally state- or district-scoped) | Create and manage tests; add questions; review submissions |

## System Admin

The System Admin runs a single organization end-to-end. They can:

- Manage all **users** in their org (create, edit, deactivate)
- Set **organization settings** — feature toggles, platform nomenclature, guides, analytics
- Create and edit any **test**, **question**, **tag**, **form**, **certificate**, or **entity**

Submission data and reports are reviewed in **Looker Studio** via [BigQuery Sync](../integrations/bigquery-sync), not inside the Portal.

If you're the person setting up Sashakt for your organization, you're probably a System Admin.

## State Admin

A State Admin is a **scoped** role — they look a lot like a System Admin, but only for data belonging to their state.

A State Admin in Maharashtra can:

- See tests assigned to Maharashtra
- Add and manage users within Maharashtra
- Use Looker Studio (via BigQuery) to review submissions from candidates registered in Maharashtra

…but cannot see anything from Karnataka.

:::info Why scoped roles?
Many Sashakt deployments cover large geographies. Scoped roles let regional teams manage their work without seeing — or accidentally editing — other regions' data.
:::

## Test Admin

A Test Admin focuses on **building and running tests**. They can:

- Create and edit tests
- Add and edit questions in the question bank

A Test Admin can be assigned a **state or district scope** — for example, a Test Admin scoped to _Pune District_ will only see tests and content tied to that district. Without a scope, a Test Admin can work across the whole organization.

Submission data flows to BigQuery for analysis in Looker Studio — it isn't reviewed inside the Portal.

This role is a good fit for subject-matter experts, training coordinators, or regional content authors who shouldn't have full admin access.

## How to tell which role you have

Open your **Profile** page in the Portal. Your role is shown at the top.

If your role doesn't match what you expected, ask your System Admin to update it. Roles can be changed at any time.
